The plan we wrote,
and the plan we kept.

A plan that never changes was never tested. Below is what we agreed before building, what moved during the build, and the reason for each move.

The drawing

Agreed first

before code

Four rules, written down before anyone opened an editor. They are the reason the three pages look like one site instead of three.

  • Three pages Home · The Plan · Team
  • One stylesheet styles.css, no inline styles
  • One palette violet, indigo, champagne gold
  • No JavaScript not even for the search box
  • Every page one image, one alt text, one clear way back

What changed

and why

Three deviations from the original plan. Each one was discussed, not drifted into.

Original plan · change · reason
In the plan What we built Why
A pale, paper-like theme A dark theme with gold accents The subject is a night-time studio idea; a dark page made the images the light source instead of the decoration.
Four pages, with a gallery Three pages, no gallery The gallery had no material behind it. Three complete pages beat four with one empty room.
A newsletter form A working documentation search We cannot receive mail, so a newsletter form would have been a prop. The search form actually submits somewhere.

What did not change

the promises
01

One stylesheet

Every rule used on every page lives in styles.css, grouped and numbered, so a reviewer can find the rule that made a thing look wrong.

02

No JavaScript

Gradients, blur, hover states and the slow aurora drift are all CSS. The one interactive thing on the site is a plain form.

03

Published, not zipped

The site lives in a subfolder of a group member's repository and is served by GitHub Pages, so the address can be opened by anyone in the class.

“Write the plan down so that changing it becomes a decision instead of an accident.”

— the note we kept at the top of the file
